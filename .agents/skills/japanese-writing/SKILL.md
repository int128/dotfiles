日本語でドキュメントを書く場合は、以下のスタイルに従ってください。

- 丁寧体 (ですます調) で統一する。
- 1文1意味で簡潔に書く。修飾語を重ねない。
- 言葉を列挙する場合は `、` で区切る。英単語を列挙する場合は `, ` (半角カンマ) で区切る。
- 曖昧表現は避け、断定的に書く。確定していない事項は「予定です」「作業中です」のように事実として明示する。
- なぜそうするのか (Why) を書く。コードなどから自明な内容 (What) は書かない。
- エッジケースの分岐を明示する。例: もし〜の場合は〜してください
- 受け身よりも能動的な動詞を選ぶ。ただし主体が不明確な場合は受け身でよい。
- 絵文字、装飾的な強調、感情表現は使わない。
- セクションは `##` や `###` で階層化する。対比や時系列で切り分ける。
- 関連資料は文書末尾の「関連資料」セクションにリンクを箇条書きで集約する。
- 対応関係・並列情報は表形式で示す。ブランチや環境、変更前と変更後など、列の意味が明確な場合は積極的に表を使う。
- 列挙は `-` の箇条書きにする。インデントで階層化する。見出し的に使う場合は `見出し:` のように末尾コロンで導入する。
- 構造・フロー・関係性は Mermaid 図で可視化する。
- 手順は番号付きリストで書く。各ステップは命令形で完結させる。
- コマンドはバッククォートで囲む。例: `git push`
- Issue や PR などの参照は番号 (`#1234`) ではなく URL を書く。
- 同一リポジトリ内のリンクは相対パス、外部リポジトリは https URL を使い分ける。
- URL の前後に文字を連結しない。
- 日時は「2026年4月上旬」「毎週火曜 12:00」のように曜日や時刻まで具体的に書く。

## チェックリスト

- 表で表現すべき対応関係を散文で書いていないか
- フロー・構造を文章だけで説明しようとしていないか。表や Mermaid を検討
- 各セクションが「何を言いたいのか」を冒頭1〜2文で示しているか
